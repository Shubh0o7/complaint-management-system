# Future Scope

The current system is intentionally complete enough for an academic demonstration while keeping its implementation understandable. Future institutional work could add SSO integration with the university identity provider, multilingual interfaces, accessibility conformance testing, mobile push notifications, immutable audit retention, data-retention policies, configurable holiday-aware SLA calendars, and integrations with student-information or help-desk systems.

Further engineering could replace the local email adapter with a managed SMTP provider, add asynchronous queues for high-volume notifications, introduce object storage with malware scanning, and add a formal administrator approval workflow for account creation. Analytics could be extended with trend forecasting only after the institution has accumulated a properly governed historical dataset.

A production rollout should also include threat modelling, independent security review, privacy impact assessment, backup and disaster-recovery testing, performance testing, and a clear grievance-retention policy. These are operational responsibilities rather than features that should be hidden behind a college-project interface.
